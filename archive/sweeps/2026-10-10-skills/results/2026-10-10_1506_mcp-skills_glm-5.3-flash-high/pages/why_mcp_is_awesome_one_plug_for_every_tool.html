The MCP Blog Built with Umbraco + MCP

Why MCP is awesome: one plug for every tool

Before Model Context Protocol, every AI integration was bespoke. Now one open protocol connects assistants to databases, design tools and even this blog's backoffice.

Before Model Context Protocol, wiring an AI assistant to your software meant building a bespoke integration for every pair: this assistant, that database, this design tool, that CMS. It was the n×m problem — every new player multiplied the work.

MCP collapses it to n+m. An assistant learns one protocol; a tool implements one server; and suddenly they all speak to each other. The tool describes its capabilities, the assistant discovers them at runtime, and no one writes glue code for a specific pairing ever again.

The best part is what it feels like in practice. An assistant that could only chat can now create a document type in your CMS, upload an image, publish a page — with permissions and confirmations you control. This very blog was built that way: schema, content and publishing all done through tool calls against Umbraco's MCP servers.

USB-C for AI applications — connect any model to any tool, once, and it just works.

— The pitch that sold the whole industry on MCP, in one sentence

And it is not just assistants. IDEs, terminal agents and CI pipelines are all adopting the same protocol, so the tool you build for one audience works for all of them. Fewer integrations, more software that actually talks to itself.
