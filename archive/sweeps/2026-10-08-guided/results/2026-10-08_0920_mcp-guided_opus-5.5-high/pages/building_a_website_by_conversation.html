Building a Website by Conversation with MCP

MCP turns a CMS into something an AI assistant can genuinely work with: schema, media and content, all through the same well-described tools.

This very blog is a small proof of the idea. The document types, the block grid, the images in the media library and the pages themselves were all created by an AI assistant talking to Umbraco over MCP. Nobody clicked through the backoffice.

Two servers split the work along a line that makes sense to humans too: a developer-facing server for schema (data types, document types, templates, media and domains) and an editor-facing server for pages, blocks and publishing.

Guardrails come with the territory

Because every action goes through a named tool with a typed input, MCP keeps an assistant on the rails. It can't wander off and poke the database directly; it can only do what the server offers, and the server can ask a human to confirm anything destructive before it happens.

The tools also teach. When a call fails, a good server explains why in a sentence, and the assistant fixes its input and tries again. Building this site involved exactly that loop, and it's a far nicer way to work than reading a stack trace.

The result is a CMS that people and assistants can share: editors keep the backoffice they know, and the repetitive setup work can be handed to an assistant that speaks the same protocol as everything else.
