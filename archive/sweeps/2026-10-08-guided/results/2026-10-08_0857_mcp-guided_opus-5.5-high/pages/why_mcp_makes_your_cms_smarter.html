Why MCP Makes Your CMS Smarter

Give an AI assistant real tools instead of copy-paste, and it stops guessing about your content model. Here is what that looks like in Umbraco.

Ask a chatbot to help with your website and it will happily invent document types, property aliases and APIs that do not exist. It is not being careless; it simply cannot see your system. All it has is what you paste into the chat.

MCP changes that. With an Umbraco MCP server connected, the assistant can look before it acts: list your document types, read a page, inspect its blocks and check which data types already exist. The guessing stops because the facts are one tool call away.

Two servers, two jobs

This very site was built with two MCP servers side by side. The developer server shapes the schema: element types, a block grid data type, page types, templates and media. The editor server handles content: creating pages, adding blocks and publishing.

Splitting the work this way mirrors how real teams operate. Developers own the structure, editors own the words, and the assistant can switch hats without ever reaching around the CMS into the database.

The result is an assistant that works with Umbraco's conventions instead of against them. That is the real superpower of MCP: not doing more, but doing it the right way.
