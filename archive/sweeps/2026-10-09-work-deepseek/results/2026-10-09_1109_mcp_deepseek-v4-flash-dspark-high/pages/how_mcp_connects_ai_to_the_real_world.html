Beyond the Chat Interface

AI models are incredibly powerful, but they've traditionally been stuck inside a chat window. To do real work — query a database, send an email, update a CMS — they need connections to the outside world. That's exactly what MCP provides.

How MCP Works

MCP follows a client-server architecture:

  • MCP Clients — AI applications like Claude Code, IDE extensions, or custom tools that need to interact with external systems
  • MCP Servers — Lightweight servers that expose tools and resources. Each server connects to one backend system (a database, a file system, an API)
  • The Protocol — A standardized JSON-RPC-based communication layer that handles tool discovery, invocation, and resource access

MCP + Umbraco: A Real Example

Take this very blog post. It was created through an MCP server connected to Umbraco — the AI agent queried the CMS, created content types, uploaded media, and published pages, all through a standardized protocol. No custom API wrappers, no brittle screen-scraping — just clean, typed tool calls mapped to Umbraco's Management API.

That's the promise of MCP: any AI tool can talk to any system, as long as both speak the same protocol.
