MCP in Practice: Building This Blog

5 October 2026

This blog is itself a case study. Every document type on this site — the front page, the posts, the three block types you are reading right now — was created over MCP, with no manual clicking in a backoffice and no hand-written database scripts. The schema was modelled in a handful of calls, the media was uploaded the same way, and the words you are reading were placed into blocks one tool call at a time.

That is the quiet promise of the protocol: if you can describe a capability, an agent can use it. Not just toy capabilities — real ones, like editing a production CMS.

The block you are reading is a rich text block inside a block grid property. The grid itself was configured over MCP with a single data type call listing three element types; the paragraphs above were inserted with one call per block. When a call failed, its error message said exactly what to fix — the protocol turns an API surface into a conversation.

That feedback loop is what separates a demo from a workflow. Schema, content and media were built by the same loop, end to end, on this very project.

“No clicks, no scripts, no migrations — just protocol calls, and a site that builds itself.”
