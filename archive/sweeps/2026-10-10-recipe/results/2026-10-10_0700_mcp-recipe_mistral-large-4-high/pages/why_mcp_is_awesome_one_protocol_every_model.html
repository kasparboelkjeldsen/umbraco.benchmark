Why MCP is awesome: one protocol, every model

One standard, any model, any client. MCP is the reason this site could be assembled by an agent without a single manual click in the backoffice.

MCP's superpower is not any single tool but the protocol itself: one standard way for models to discover and call capabilities, implemented by every major client and server. Write a tool server once and it lights up in Claude, in editors, in CI agents — anywhere that speaks MCP. The blog you are reading was assembled by exactly such a client, driving two MCP servers against a local Umbraco instance.

For a content platform this is a big deal. Umbraco ships a management API; the MCP server wraps it as tools; the agent composes those tools into a site. Schema first, then content, then a domain, then a published page — each step a tool call, each result a confirmation. The same steps a human would take in the backoffice, minus the clicking.

There is also something quietly awesome about building a site this way: the content model and the content are created in one continuous conversation. The document types that shape the blog exist moments before the posts that use them, and the generated models the Razor views compile against appear as soon as the schema is saved. Model, content, code — one loop, no context switching, no 'export the schema and paste it somewhere' dance.

If you have ever wanted your CMS to feel less like a place you visit and more like a place you talk to, MCP is the bridge. This blog is the proof: two posts, a front page, five photos, a domain on / — all of it through the protocol.

“One protocol, every model, every tool — MCP is the universal adapter the agent ecosystem was missing.”
