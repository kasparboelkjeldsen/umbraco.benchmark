Why MCP Is Awesome

The Model Context Protocol turns your CMS from a black box into a toolbox. Here is why that changes everything.

What MCP actually is

MCP — the Model Context Protocol — is an open standard for connecting AI agents to the systems they work with. Think of it as USB-C for AI: one plug, many devices. An agent that speaks MCP can discover what a server offers, call those capabilities with structured inputs, and get structured results back.

Umbraco ships an MCP server that exposes the CMS's own management API as tools: read the content tree, create document types, publish pages, upload media. No screen-scraping, no custom integrations — the agent uses the same API a backoffice user would.

“An API you can call is worth a thousand prompts you have to babysit.”

Apocryphal, but true

Why that is awesome

  • Tools, not prompts. The agent calls real API operations — create, update, publish — instead of hoping a prompt produces the right JSON.
  • Schema first. Every tool has a typed input and output, so results are predictable and errors are loud.
  • Least privilege. The MCP server authenticates with its own API user and scopes what an agent may do.
  • Composable. The same server works from any MCP client — CLI agents, IDEs, chat apps.

That is the whole trick: the CMS stops being a black box and becomes a toolbox the agent can actually use.
