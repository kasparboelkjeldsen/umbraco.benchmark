Why MCP Is Awesome for Editors

MCP meets editors where they already work: the backoffice stays the source of truth, and the agent does the typing.

If you spend your days in the Umbraco backoffice, MCP is awesome for a very concrete reason: it meets you where you already work. The agent is just another client of the same management API — it creates the draft, sets the properties, adds the blocks, and asks you to hit publish.

You keep the editorial controls. The agent gets the typing.

“The model proposes, the CMS disposes — in the best possible way.”

A very tired integrator

Where this is going

Every block on this page was placed by an agent through the Umbraco MCP server: the schema, the content, the media, the publish. The Razor views rendering it were written the same afternoon. That is the whole pitch — an open protocol, an honest API, and a CMS that was built to be extended.
