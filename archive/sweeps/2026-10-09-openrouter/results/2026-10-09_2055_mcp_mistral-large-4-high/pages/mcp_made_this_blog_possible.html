MCP Made This Blog Possible

Schema, content, media — an agent built this whole site by talking to Umbraco over MCP.

This blog — the document types, the block element types, the templates, these very words, the photos — was created end to end by an agent talking to Umbraco's management API over MCP. Not one click in the backoffice.

Schema first, content second

The agent modeled the schema before writing a word: a Blog Front Page and a Blog Post document type, plus three block element types — hero, rich text, image — each filed into the right folder by the project's own rules. Only then did it create content, because content needs a schema to land in.

Blocks all the way down

Every page body is a block grid. The hero, the paragraphs, the photos — all blocks, rendered by Umbraco's own pipeline, each block a small view component behind a thin adapter partial. No custom renderers, no wrapper models — just Umbraco's conventions.

Then the pipeline: stop the site, rebuild so the generated models exist, write the Razor, restart. Three steps, one flow, and a blog that renders. That is MCP being awesome — the agent did the plumbing so the site could simply exist.
