MCP in Practice: The Site You Are Reading Right Now

This blog was modeled, populated and published through the Umbraco MCP server — a live demonstration of exactly what the first post praises.

MCP in Practice

The proof is the page you are reading

<p>This site is not an illustration — it is a receipt. Every document type, every data type, every template and every piece of content you can see was created through the <strong>Umbraco MCP server</strong>: typed tool calls against a management API, no hand-editing, no migration scripts.</p><p>Notice what that felt like from the outside. The agent asked for a blog; the CMS exposed <em>modeling</em> as tools and the agent composed them — element types here, a block grid there, content snapped into the slots the schema defines. There was no scraping of a UI and no brittle macro recorder, because the protocol speaks in the CMS's own vocabulary.</p>
<p>And that is the quiet lesson of MCP: when the surface area between an agent and a system is <em>precisely</em> defined, the agent stops guessing. It reads the schema, follows the rules, and writes values that validate. The result you are reading was assembled block by block — hero, rich text, image — each one a protocol call, not a mouse click.</p><p>The tools did not make the agent smart. They made the agent <em>grounded</em> — and that is the part worth standardizing.</p>
