Why MCP is awesome, part 2

Content without the clicking: how an MCP server turns a CMS into something an agent can build with.

In part one we covered the idea. Here is what it feels like in practice.

Modelling content is a sequence of small, checkable steps: create an element type, move it into the right folder, create the data type it needs, then read it back to confirm it took. Each step is a tool call with a clear result.

The part I like most is the feedback loop. When a block payload is wrong it fails quietly, so the habit is to read structural writes back straight away. MCP makes that easy because reading is just another tool, and the agent and the developer end up looking at the same facts.

MCP is awesome because it makes the boring plumbing legible. That leaves more room for the interesting decisions.
