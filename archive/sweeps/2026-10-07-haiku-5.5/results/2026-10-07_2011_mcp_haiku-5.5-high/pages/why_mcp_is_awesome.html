Why MCP is awesome

The Model Context Protocol gives AI assistants one standard, auditable way to reach the systems we already run.

Every integration used to be a bespoke adapter. Each assistant, each tool and each CMS needed its own glue code, its own auth story and its own idea of what a request looks like.

The Model Context Protocol (MCP) replaces that patchwork with one contract. A server exposes capabilities as named tools with typed inputs. A client discovers them and calls them. That is the whole idea, and it is a good one.

Why it is awesome: it is boring in the right ways. The tools are declared with schemas, so mistakes are caught at the boundary. The same server works for any MCP client, and because the interface is explicit you can read exactly what an agent is allowed to do.

In this project, the Umbraco MCP server lets an agent model document types, create content and manage media without a single click in the back office.
