Building Tools with MCP: A Practical Guide

October 5, 2026

Building your first MCP server is remarkably straightforward. At its heart, an MCP server is just a program that speaks JSON-RPC over stdio or SSE. You define tools (functions the agent can call), resources (data the agent can read), and prompts (templates to scaffold interactions).

The official SDKs — available for Python, TypeScript, Java, and Kotlin — handle all the protocol plumbing. You focus on what your tool does, not how to marshal JSON.

Here is a quick example of what a tool definition looks like in the TypeScript SDK:

server.tool("get-weather",
  { city: z.string() },
  async ({ city }) => {
    const data = await weatherApi.fetch(city)
    return { content: [{ type: "text", text: data.summary }] }
  }
)

That is it — one function call registers a tool. The SDK handles input validation (via Zod schemas), JSON-RPC wrapping, error reporting, and streaming. Your agent discovers it automatically on connection.
